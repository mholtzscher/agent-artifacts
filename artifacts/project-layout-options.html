01

Runtime-first layout

Make deployment boundaries impossible to miss. Each runtime owns its composition and concrete adapters. 

src/
  domain/
  render/
  http/
    Http.ts

  publishing/
    ArtifactPublishing.ts

  runtimes/
    bun/
      Program.ts
      BunApp.ts
      SqliteArtifactDatabase.ts
      SqliteArtifactRepository.ts
      FileArtifactSourceStorage.ts
    cloudflare/
      Worker.ts
      CloudflareApp.ts
      CloudflareBindings.ts
      D1ArtifactRepository.ts
      R2ArtifactSourceStorage.ts

  shared/
    AppRouter.ts
    AppLayers.ts

Good fit when

  • Deployment/debugging is the main navigation path.
  • You want hard visual separation between Bun and Worker code.
  • Bundle safety matters more than keeping adapters near interfaces.

Watch out for

  • Interfaces and implementations may drift apart.
  • Shared app services can become a vague dumping ground.

02

Port / adapters layout

Use explicit service contracts in ports, and put concrete runtime/backend implementations under adapters. 

src/
  domain/
  render/
  http/
  application/
    publishing/

  ports/
    ArtifactRepository.ts
    ArtifactSourceStorage.ts
    AppConfig.ts

  adapters/
    bun/
      Program.ts
      BunApp.ts
      sqlite/
      filesystem/
    cloudflare/
      Worker.ts
      CloudflareApp.ts
      d1/
      r2/

  layers/
    BunLive.ts
    CloudflareLive.ts

Good fit when

  • You expect more backend implementations later.
  • You want service contracts to be first-class architectural objects.
  • Tests should run the same port contract against multiple adapters.

Watch out for

  • More abstract terminology than the product needs today.
  • Can feel enterprise-y if the adapter count stays small.

03

Capability-first layout

Keep each capability’s interface and implementations together. This is the smallest change from the current code while making multiple backends obvious. 

src/
  domain/
  render/
  http/
  publishing/

  repository/
    ArtifactRepository.ts
    sqlite/
      ArtifactDatabase.ts
      SqliteArtifactRepository.ts
    d1/
      D1ArtifactRepository.ts

  source-storage/
    ArtifactSourceStorage.ts
    filesystem/
      FileArtifactSourceStorage.ts
    r2/
      R2ArtifactSourceStorage.ts

  runtime/
    bun/
      Program.ts
      BunApp.ts
    cloudflare/
      Worker.ts
      CloudflareApp.ts
      CloudflareBindings.ts

Good fit when

  • Developers navigate by capability: repository, source storage, config.
  • You want SQLite vs D1 and filesystem vs R2 to be easy to compare.
  • You want a surgical migration from the current structure.

Watch out for

  • Runtime composition is spread across capability folders.
  • Shared modules need import discipline to avoid pulling runtime-only code.
recommended nowleast churnbackend comparison
04

Effect layer-oriented layout

Organize around Layer construction and provisioning. This mirrors how the app actually starts. 

src/
  domain/
  http/
  render/
  publishing/

  services/
    ArtifactRepository.ts
    ArtifactSourceStorage.ts
    AppConfig.ts

  implementations/
    sqlite/
    filesystem/
    d1/
    r2/
    config/

  layers/
    shared/
      AppRouteLive.ts
      PublishingLive.ts
    bun/
      BunDataLive.ts
      BunHttpLive.ts
      BunAppLive.ts
    cloudflare/
      CloudflareDataLive.ts
      CloudflareAppLive.ts

  entrypoints/
    Program.ts
    Worker.ts

Good fit when

  • Effect composition is the primary source of truth.
  • You want all Layer.provide decisions easy to audit.
  • Runtime wiring bugs are more common than domain bugs.

Watch out for

  • Less domain-oriented than the rest of the project language.
  • New contributors must understand Effect Layers to navigate well.

Recommendation

Choose Option 3: Capability-first layout now. It reflects the actual architecture — one domain/application layer, two runtime compositions, and paired backend implementations — without introducing a ports/adapters vocabulary heavier than the current app needs. 

src/
  repository/
    ArtifactRepository.ts
    sqlite/
    d1/

  source-storage/
    ArtifactSourceStorage.ts
    filesystem/
    r2/

  runtime/
    bun/
    cloudflare/
