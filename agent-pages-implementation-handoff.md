# Agent Artifacts — Implementation Handoff

## Project Summary

Build **Agent Artifacts**, a self-hosted, Cloudflare Tunnel-exposed public artifact feed for markdown and HTML files generated by coding agents.

The app should let a coding agent, CLI, or slash command publish generated artifacts to a public website. All read routes are public. All write routes are protected by a single shared write key passed via the `X-Write-Key` header.

The initial use case is simple:

```bash
agent-pages publish ./PLAN.md
```

The command uploads the file to a homelab-hosted app and returns a public rendered URL plus a source URL.

Example response:

```text
Published:
https://artifacts.example.com/a/conveyor-governance-plan-k29d

Source:
https://artifacts.example.com/source/conveyor-governance-plan-k29d
```

## Product Goals

### Primary Goals

- Publicly render and share agent-generated markdown and HTML artifacts.
- Provide a public history/gallery of generated artifacts.
- Support project, repo, tag, and collection organization.
- Provide a dead-simple upload API for coding agents.
- Run self-hosted in Docker on a homelab.
- Be exposed publicly through Cloudflare Tunnel.
- Use one write key for write endpoints.
- Keep storage simple: SQLite metadata plus filesystem artifact storage.

### Non-Goals for MVP

Do **not** build these in v1:

- User accounts
- Login/dashboard auth
- Private artifacts
- Password-protected links
- Cloudflare Access integration
- Multi-user write key management
- Full analytics
- Comments
- Billing
- Complex admin UI
- MinIO/S3/R2 storage
- Kubernetes deployment

These can be considered later.

## High-Level Architecture

### Components

1. **Web app/API**
   - Serves public pages.
   - Accepts artifact uploads.
   - Renders markdown and HTML.
   - Provides JSON APIs.
   - Protects write endpoints using `X-Write-Key`.

2. **SQLite database**
   - Stores artifact metadata.
   - Stores project/repo/tag/collection relationships.
   - Does not store large file content.

3. **Filesystem storage**
   - Stores source files.
   - Stores rendered HTML cache.
   - Stores metadata snapshots if useful.
   - Mounted as a Docker volume.

4. **CLI**
   - Uploads files.
   - Adds metadata.
   - Auto-detects git repo, branch, and commit.
   - Prints public URLs.

5. **Cloudflare Tunnel**
   - Exposes the homelab service publicly.
   - No direct port forwarding required.

## Suggested Tech Stack

Preferred options:

- Runtime: Node.js
- App framework: Hono, Fastify, Elysia, or SvelteKit
- Language: TypeScript
- DB: SQLite
- SQLite ORM/query layer: Drizzle, Kysely, or plain SQL
- Markdown rendering: `markdown-it`, `marked`, or `micromark`
- Sanitization: `sanitize-html` or equivalent
- Syntax highlighting: Shiki or Highlight.js
- CLI: TypeScript-based Node CLI
- Container: Docker

Given the user's existing preferences, **TypeScript + SQLite + Docker** is a strong fit.

A simple Hono or Fastify app may be better than SvelteKit for v1 if the goal is speed and simplicity. SvelteKit is fine if the frontend is expected to become more polished.

These routes require no authentication:


### Protected Write Routes

These require the `X-Write-Key` header:

```text
POST   /api/artifacts
PATCH  /api/artifacts/:slug

```

MVP may only implement:

```text
POST /api/artifacts
GET  /
GET  /a/:slug
GET  /source/:slug
GET  /api/artifacts
```

## Write Key Auth

Use a single shared write key.

Do **not** use full bearer token infrastructure for MVP. Do **not** build write key tables, scopes, revocation, or per-agent keys.

### Request Header

```http
X-Write-Key: <secret>
```

### Example Request

```bash
curl -X POST https://artifacts.example.com/api/artifacts \
  -H "X-Write-Key: $AGENT_ARTIFACTS_WRITE_KEY" \
  -F "file=@PLAN.md" \
  -F "title=Foundry Governance Plan" \
  -F "project=foundry"
```

### Middleware Pseudocode

```ts
function requireApiKey(request: Request, expectedApiKey: string): Response | null {
  const provided = request.headers.get("x-api-key");

  if (!provided) {
    return new Response("Missing write key", { status: 401 });
  }

  if (provided !== expectedApiKey) {
    return new Response("Invalid write key", { status: 403 });
  }

  return null;
}
```

### Environment Variable

```env
AGENT_ARTIFACTS_WRITE_KEY=ap_some_long_random_value
```

Generate a key:

```bash
echo "ap_$(openssl rand -base64 32 | tr -d '=+/')"
```

## Database Schema

### artifacts

```sql
create table artifacts (
  id text primary key,
  slug text not null unique,
  title text not null,
  summary text,
  description text,
  artifact_type text not null, -- markdown, html, text, json, svg, unknown
  mime_type text,
  source_filename text not null,
  source_path text not null,
  rendered_path text,
  sha256 text not null,
  size_bytes integer not null,
  project text,
  repo_owner text,
  repo_name text,
  repo_full_name text,
  branch text,
  commit_sha text,
  dirty integer default 0,
  agent text,
  generator text,
  created_at text not null,
  updated_at text not null
);
```

### tags

```sql
create table tags (
  id text primary key,
  name text not null unique,
  created_at text not null
);
```

### artifact_tags

```sql
create table artifact_tags (
  artifact_id text not null,
  tag_id text not null,
  primary key (artifact_id, tag_id),
  foreign key (artifact_id) references artifacts(id) on delete cascade,
  foreign key (tag_id) references tags(id) on delete cascade
);
```

### collections

```sql
create table collections (
  id text primary key,
  slug text not null unique,
  title text not null,
  description text,
  project text,
  repo_full_name text,
  created_at text not null,
  updated_at text not null
);
```

### collection_artifacts

```sql
create table collection_artifacts (
  collection_id text not null,
  artifact_id text not null,
  position integer not null default 0,
  primary key (collection_id, artifact_id),
  foreign key (collection_id) references collections(id) on delete cascade,
  foreign key (artifact_id) references artifacts(id) on delete cascade
);
```

## Artifact Types

MVP should support:

- Markdown: `.md`, `.markdown`
- HTML: `.html`, `.htm`
- Text: `.txt`
- JSON: `.json`
- SVG: `.svg`

### Markdown Rendering

Markdown should be rendered to HTML.

Support:

- GitHub-flavored markdown
- Tables
- Task lists
- Fenced code blocks
- Syntax highlighting
- Links
- Images
- Table of contents if easy

Sanitize rendered markdown HTML.

### HTML Rendering

For uploaded HTML artifacts, do not inject the HTML directly into the app shell.

Preferred behavior:

```text
/a/:slug       shows app wrapper page
/embed/:slug   serves uploaded HTML for iframe preview
/source/:slug     raw source
```

In `/a/:slug`, render HTML artifacts inside an iframe:

```html
<iframe src="/embed/my-html-artifact" sandbox="allow-same-origin"></iframe>
```

Consider a strict Content Security Policy.

MVP can also choose to show raw HTML source first and add iframe preview later.

## Slug Generation

Generate readable slugs.

Input:

```text
Foundry Governance Plan
```

Output:

```text
foundry-governance-plan-k29d
```

Rules:

- Lowercase
- Replace non-alphanumeric runs with `-`
- Trim leading/trailing `-`
- Append short random suffix
- Ensure uniqueness

If no title is provided, infer title from filename.

Example:

```text
PLAN.md -> plan-a82k
```

## Security Notes

Even though all artifacts are public, protect writes.

Minimum protections:

- Require `X-Write-Key` on all write endpoints.
- Never accept writes without the key.
- Do not allow path traversal in uploaded filenames.
- Generate server-side storage paths.
- Sanitize rendered markdown.
- Do not directly inject uploaded HTML into the app layout.
- Use iframe sandboxing for HTML previews.
- Put upload size limits in place.
- Consider rate limiting later.
- Avoid logging the write key.

Recommended upload size limit for MVP:

```text
10 MB per artifact
```

This can be configurable.

## Acceptance Criteria for v1

A successful MVP means:

1. App runs in Docker.
2. App can be exposed through Cloudflare Tunnel.
3. Public homepage lists uploaded artifacts.
4. `POST /api/artifacts` requires `X-Write-Key`.
5. Markdown file can be uploaded.
6. Markdown file gets rendered to a public page.
7. Raw source is publicly available.
8. CLI can publish a file and print URLs.
9. Metadata includes title, slug, type, created date, and optional project/repo/tags.
10. Data persists across container restarts.
